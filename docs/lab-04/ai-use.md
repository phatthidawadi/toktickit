## Reflection

### Specification-Agent Use
Using Gemini via Antigravity during the Sprint 4 contract phase significantly accelerated the translation of stakeholder requirements into formal engineering specifications. The agent was instrumental in defining unambiguous boundaries for the Actions Taken parent-child relationship, constructing the complete 8-state transition matrix, and mapping Acceptance Criteria across nine distinct quality assurance layers (Unit, API, Component, Style, Responsive, AuthZ, Migration, E2E, and Performance-Smoke).

Peer review by `@chanya06` highlighted critical nuances—specifically ensuring complete alignment between the status transition authorization matrix and the API endpoints (including requester-only cancellation endpoint scoping), explicitly requiring mandatory optimistic locking versions across all mutation routes, and including performance-smoke benchmarks. Collaborating with the AI agent enabled rapid, consistent updates across all contract documents simultaneously.

### Coding-Agent Use
Throughout the implementation of Issues 27 through 33, the AI agent served as an effective pair programmer for scaffolding boilerplate routes, generating responsive Tailwind/CSS layouts, and drafting initial integration tests. However, close human auditing and strict technical oversight were essential in several critical areas:

1. **Database Schema & Type Safety:** When Prisma generates TypeScript types from enums (such as `TicketStatus`), general string arrays in server controllers (`string[]`) caused TypeScript compilation failures during `npm --prefix server run build`. Identifying and resolving this required explicitly importing and typing `TicketStatus[]`, ensuring zero build errors.
2. **E2E Testing Pitfalls & False Positives:** Automated test generation initially produced tests that relied on hardcoded auto-incrementing database IDs (`/api/tickets/2/actions`), which failed after database resets because SQLite does not reset sequence counters on table truncations. Furthermore, conditional `if` wrappers around assertions masked failures. Human-led intervention guided the agent to extract dynamic identifiers directly from DOM element attributes and enforce unconditional `expect().toBeVisible()` assertions, guaranteeing genuine test coverage.
3. **Accessibility Compliance:** While ARIA role tags were generated accurately, true keyboard accessibility required implementing active `Tab` and `Shift + Tab` focus boundary trapping inside modal dialogs so keyboard users cannot navigate behind active modals, fulfilling WCAG 2.4.3.
4. **Idempotency & Clean Builds:** Ensuring all 191 automated tests (115 server, 52 client, 24 E2E) run idempotently and pass 100% across Chromium Desktop, Tablet, and Mobile devices required continuous cross-checking against Lab 1–3 legacy regressions.
